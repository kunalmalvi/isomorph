## Registry concurrency left half-done

`EvidenceLog.append` and the audit `_log` both use `_file_lock`, but `ModelRegistry.propose` reads `len(self.history())` and writes the version file without it. The gate run between those steps is slow (two metric evaluations), so the window is wide if the CLI and a running server both cycle. Both would write `vN.json`, and the later write wins while the audit log shows two proposes for one id. This needs an explicit user action in both processes at the same moment, so it does not block.

## Rejected-candidate skip is keyed on exact evidence ids

`last_rejected_for` matches only when the config and the sorted evidence ids are identical. Any new evidence event changes the ids and permits a new gate run, even if it does not affect the candidate. That is the safe direction (it retests rather than suppresses). A rejected candidate is therefore retried after every unrelated event, which costs one gate evaluation each time.

## Test coverage
